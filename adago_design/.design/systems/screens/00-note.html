adago-design · 体系管理弹层 v2 · 设计说明
从「表单常驻」到「列表 + 详情」
960 × 720先设计后实现v2

现版弹层把「新增表单」固定在上半屏，系统列表被压到 6 行、必须滚动；没有搜索与过滤， 状态（内置/自定义/已停用）只能靠一排小字；每一行都同时暴露 停用 / 编辑 / 恢复默认 三个按钮； 编辑与查看混在一起。本次重设计只改管理弹层的结构：列表 + 详情两栏、搜索 + 分段过滤、 编辑按需进入，新增/编辑共用右侧面板；后端 API 与管理能力不变。

01 · 现状审计截图实测
问题后果
创建表单常驻占上半屏列表只剩 6 行可见，8 套内置体系必须滚动；用户每次只想管理时要先穿过表单
无搜索 / 无过滤体系一多（自定义 5+）找不到；停用体系只能混在列表里靠小字辨认
每行三个按钮常驻视觉噪音大，行宽被吃掉；「恢复默认」在没有覆盖时也显示为可用外观
详情与编辑混排内置体系只能改显示信息，却和整体 JSON 编辑放在同一张表单里，边界不清
760px 单栏两列表单厂商、基底、主色、ID 挤在两列；色板预览无处放，主色只有 6px 小点
空态/确认缺失搜索无结果无提示；移除只有系统 confirm，语气与纸墨体系脱节
02 · 目标与原则不新增能力
  • 列表优先：打开先看到 9 个体系与状态，操作按需展开。
  • 两栏：左 360 列表（搜索 + 过滤），右 560 详情/编辑；宽 960。
  • 状态可视：色块、内置/自定义、已停用、已改信息，一眼分辨。
  • 操作收敛：行内只留开关，详情页做编辑；删除走确认。
  • 编辑分层：内置=显示信息；自定义=显示信息 / 完整 JSON。
  • 同源令牌：纸墨色、圆角、字号全部沿用 --ui-*，不新增品牌色。

05 · 决策记录有争议的点先定
  • 行内开关 vs 停用按钮：用开关表达启用态，语义是「是否进入选择面」；停用原因在详情横幅里说明。
  • 详情即编辑？：不。详情保持只读，点「编辑显示信息」才进表单，避免误改内置体系。
  • 内置 Token 不可改：只改显示信息；整体 JSON 编辑仅对自定义开放（页签隔离）。
  • 新增与编辑共用面板：同一套字段与校验，减少两套表单的漂移；新增多一块色板预览。
  • 列表过滤不改变数据：过滤只是视图；搜索匹配名称/厂商/ID。
  • 删除确认沿用 uiConfirm：危险按钮 + 说明「画布上的稿不受影响」。
06 · 非目标本轮不做
  • 不做 Token 逐项可视化编辑器（仍用 JSON）。
  • 不做拖拽排序 / 分组自定义。
  • 不改 HTTP API、MCP 工具与数据格式。
  • 不改侧栏目录本身的视觉（只加「管理」入口）。

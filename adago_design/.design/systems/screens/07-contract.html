01 · DOM 结构index.html #sys-modal
层元素职责
头.sm-head标题 + 总数 chip + 搜索（230）+ 新增体系 + 关闭
左.sm-left过滤条 .segs + 列表 .sm-list（行 .sys-row）
右.sm-right.det 详情 / .form 新增编辑（同一容器切换）
脚.det-foot / .form-foot只读提示 + 恢复默认 / 取消 + 保存

复用现有 .modal / .modal__mask；宽度类改为 .modal__box--wide 960。 详情与编辑用同一个右栏容器，靠 JS 切换 data-mode（detail / create / edit / edit-json）。

02 · 数据字段沿用 /api/catalog/systems
字段用途
id / name / vendor / family行与详情标题、meta
builtin / disabled / overriddenchip、开关、恢复默认可用性、移除按钮
primary主色块 + 色值 + 编辑预填
summary / description详情显示信息区
detail.light.*Token 概览计数（colors / type.levels / spacing / radius）

列表一次拉 ?all=1；详情不额外请求（字段已够），仅自定义 JSON 页签请求 /{id}/json。

03 · 状态与交互一个弹层五种模式
模式右栏进入 / 退出
detail只读详情 + 编辑/恢复默认/移除选中行；Esc 关闭弹层
create新增表单 + 色板预览「新增体系」/ n；返回或 Esc 回详情
edit显示信息表单「编辑显示信息」/ Enter；保存回详情
edit-json自定义 JSON 页签编辑里切页签；保存成功回详情
empty无匹配 / 未选中引导搜索无结果；清空搜索恢复列表

开关直接调 POST /{id}/state；成功后重拉列表并保留选中；删除走 uiConfirm 后 DELETE。 任何变更后同步刷新侧栏 loadCatalog()，并收起体系详情。

05 · 接口全部已有
GET /api/catalog/systems?all=1列表（含停用）
GET /api/catalog/systems/{id}/json自定义 JSON
POST /api/catalog/systems新增（品牌派生）
PUT /api/catalog/systems/{id}显示信息或整体 JSON
POST /{id}/state · POST /{id}/reset停用启用 / 恢复默认
DELETE /{id}移除自定义

错误码沿用：unknown_system / system_duplicate / system_builtin_protected / invalid_system。 行内错误展示取 err.message；JSON 错误原样展示（含 invalid_system 前缀）。

07 · 风险与兼容回退容易

不做后端变更：失败时只需回退 systems-admin.js + #sys-modal 骨架即可回到 v1； 数据文件（system-settings.json / custom-systems）不受影响。

深色：沿用 --ui-* 翻转；主色块本身是数据，不参与主题推导。

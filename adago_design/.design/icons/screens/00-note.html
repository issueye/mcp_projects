02 · 目标与原则与体系管理同构
  • 列表优先：打开先看到全部图标与启用态，浏览成本最低。
  • 两栏：左 360 列表（搜索 + 全部/内置/自定义/已停用），右 560 详情/表单。
  • glyph 说话：每行先用 24 网格 glyph 识别，名称用等宽字体。
  • 内置只读 SVG：可停用、可改分组/别名，不可改路径、不可删。
  • 自定义可控：粘贴 SVG 即入库，可整体编辑、移除；移除前明确提示引用影响。
  • 同源令牌：沿用 .sm / .sys-row / .sw / .det / .field，不新增品牌色。

05 · 决策记录有争议的点先定
  • 停用语义：停用只从「选择面」隐藏（列表计数、搜索、design_icons、组件/页面预览的图标选择）；精灵仍包含全部已注册图标，避免已有模板里的 {{icon:close}} 渲染成空白。
  • 名称即 ID：不减名字（改名会让画布上已有 #ds-ic-* 引用与设计稿静默失效）；要换名就新增 + 移除旧的。
  • 内置图标为何只读 SVG：内置路径是视觉基线，改它等于改所有体系组件的观感；需要不同形态就新增自定义图标。
  • 自定义图标存 JSON：custom-icons/<name>.json 同时装 SVG 与分组/别名，单文件可同步、可走 git；不把元信息塞进 SVG 注释。
  • 不新增画布精灵：画布 chrome 用构建期 icons.js；自定义图标只在设计稿预览与图标管理里出现，运行期不改画布 UI 自身图标。
06 · 验收口径可执行
  • 新增 brand-mark（#RRGGBB 填充 SVG）后：列表计数 +1，design_icons 能搜到，预览可引用。
  • 停用 close 后：列表计数 -1，design_icons 不再返回，但旧模板里的引用仍能渲染出 glyph。
  • 内置图标详情无「删除」；自定义图标详情有「移除」，确认后回到列表。
  • 非法 SVG（<script>、外链 href、<text>）保存时被拒并给出原因。
  • 重启应用后自定义图标与停用状态仍在。

把画布整理成一份可交付的文稿
A4 · 一稿一页原生 / 浏览器v1

项目已经能导出 JSON（换机器继续编辑）和 HTML（在浏览器里看整块画布），但没有第三种东西： 可以发出去评审、归档、打印的交付物。本次不新增设计能力，只把「项目里的稿」按阅读顺序 装订成一份多页 PDF：封面交代项目身份，概览汇总体系与构成，索引给出页码，一张稿一页。 原生窗口下直接下载文件；浏览器形态退化为打印页「另存为 PDF」。

01 · 现状审计为什么需要文稿
现状后果
JSON 导出是工程文件收件人要有 adago-design 才能打开；评审者只想要一份能翻的东西
canvas_export 是一张 HTML 板带坐标、可拖动，适合看画布；打印会连工具条/浮窗一起印，也没有页码
截图只能一张一张回传多稿评审要来回切文件；顺序、项目身份、体系说明都散了
浏览器打印不可控没有专用文稿页时，@page、分页、背景色都靠用户手调
桌面端没有 PDF 能力原生窗口只能把画布交给浏览器或截图工具
02 · 目标与原则本轮只做交付
  • 一稿一页：评审能按页批注，页码可引用。
  • 按画布顺序：上→下、左→右，不按创建时间。
  • 项目身份前置：封面 + 概览先交代项目、体系、构成。
  • 不改数据：只读节点元数据，不写盘、不迁移。
  • 原生优先：隐藏窗口 + WebView2 PrintToPDF，自动下载。
  • 浏览器可退：同一文稿页 + 打印对话框，不另做一套版式。
  • 纸墨同源：印刷色板与界面令牌同源，深色主题不影响文稿。
03 · 文稿结构页序 = 阅读顺序
页内容
1封面：项目名 / 备注 / 设计稿 · 体系 · 分组框 · 文稿页计数 / 生成时间
2概览：项目信息、设计体系、设计稿构成、文稿结构、项目备注
3..k设计索引：# / 设计稿 / 体系 / 类型 / 画板 / 尺寸 / 文稿页；14 或 18 行分页
k+1..逐稿页：编号 / 标题 / 体系 / 类型 / 画板 / 尺寸 / 等比预览 / 来源 / 页码

页数 = 2 + 索引页数 + 设计稿数；空项目固定 3 页（封面 + 概览 + 空态）。 索引最后一列直接指向逐稿页，评审可以在 PDF 阅读器里按页码跳。

05 · 决策记录有争议的点先定
  • PDF 还是 PPT？PDF：评审/归档/打印通用，不需要对方装工具；不引入演示动画。
  • 逐稿页 vs 缩略拼版？逐稿页：一张稿占一页，能看清；缩略拼版只适合目录，不适合批注。
  • 分组框要不要成页？不要：它只是背板，单独成页会得到空白框，只在统计里出现。
  • 纸张方向谁决定？稿件宽高比多数票；平票取纵向（手机稿优先按 100% 印出）。
  • 服务端光栅化还是原生打印？原生 PrintToPDF：文字仍是矢量、可复制可搜索；不引入 Chromium 依赖。
  • 浏览器怎么办？同一文稿页 + ?print=1；不自研第二套 PDF 版式，避免漂移。
  • 文稿跟界面主题吗？不跟：交付物固定纸面 + 墨封面，避免深色主题把打印变成整页黑底。
06 · 非目标本轮不做
  • 不做全部项目合并文稿（多封面/多目录另议）。
  • 不做 PDF 内批注/评论（交给阅读器）。
  • 不改 JSON 导入导出、数据格式与既有 API。
  • 不做 MCP 工具（PDF 需要原生窗口，UI/HTTP 先跑通；后续按需开放）。
  • 不做在线预览器、不做 Figma/InDesign 交换格式。

同一份文稿页，两条渲染出口
不改数据格式原生 + 浏览器v1

服务端只负责「项目 → 文稿 HTML」：canvas.PrintDocument 纯函数、只读节点元数据， 不写盘、不迁移。PDF 容器交给两条出口：原生隐藏窗口的 WebView2 PrintToPDF， 或浏览器的打印对话框。前端两个入口共用 exportProjectPDF()，不各写一套。

01 · 路由HTTP
方法 / 路径职责
GET /projects/{id}/print只读文稿页；?print=1 就绪后 window.print()
POST /api/projects/{id}/pdf原生生成 PDF；返回 application/pdf + Content-Disposition
GET /api/projects/{id}/export不变：JSON 工程文件

PDF 端点无请求体；写操作仍走 Host 回环 + Origin 同源。文件名 <项目名>-系统设计文稿-YYYYMMDD-HHmm.pdf，ASCII 兜底 + RFC 5987 的 filename* 保留中文。

1项目校验→ 2过滤 frame→ 3方向→ 4渲染→ 5下载
02 · 数据只读
字段用途
title / system / kind标题、体系摘要、类型；frame 过滤
artboard / width / height画板、尺寸、缩放与纸张方向
html逐稿页 srcdoc；仅作属性值，不拼接
tags / id / updated_at页脚来源与更新时间
x / y阅读顺序（64px 行桶 + X），不进入 PDF 坐标
Project.name/note/canvas封面、概览、文件名

体系名称 / 厂商 / 主色来自 Catalog.SystemSummaries()；目录未注入时退化为体系 ID。已停用体系仍按 ID 显示，历史稿不丢。

03 · 状态与错误稳定 code
状态code前端行为
404unknown_projecttoast；提示 project_list
409empty_projecttoast + hint（分组框不单独成页）
501pdf_unavailable自动打开发印页，另存为 PDF
502pdf_failedtoast 原因 + 回退打印页
200—Blob 下载 + 成功 toast（含 KB）

请求前 toastStay() 常驻；成功/失败由下一次 toast() 接管。所有文案进 ui.js 体系，不用原生 confirm/prompt。

07 · 兼容与风险回退容易

不改数据：失败时回退前端两个入口即可，canvas.json 与已有 JSON 导出不受影响。
大项目：45s 超时 + 502 原因提示；后续可分批或只导选中稿。
混排：一份 PDF 一种纸张，少数派等比缩小；后续可分卷合并。
WebView2：不可用 / 加载失败 → 打印页；服务端不引入浏览器引擎。
